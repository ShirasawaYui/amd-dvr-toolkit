# AMD DVR Toolkit

> Fix toolkit for the AMD Adrenalin "record button does nothing" bug (DVR scene-conversion silent failure).
> AMD 桌面录制/即时重放「点击无反应」的根因分析与修复工具包。

本仓库只包含脚本与文档，**不包含任何 AMD 官方二进制文件**（原版备份由脚本在首次运行时自动生成）。

2026-10-17 首次验收（驱动 26.20.15.02）；2026-10-23 驱动升级至 26.20.15.07 后重新适配并复核通过——新驱动**未修复**该 bug，补丁点与清单位置原样不变。

---

## 一、问题现象

点击录制按钮后**毫无反应**：没有报错、没有文件落盘、界面上什么都不会发生。重启电脑有时能好一阵，之后又复发——同一套操作，成败看起来像"玄学"。

引擎日志（`%LOCALAPPDATA%\AMD\CN\dvrlog*.txt`）里能看到签名错误串：

```
Failed to send scene conversion to CN
```

（该错误串全网零命中，属 AMD 未公开的内部错误。）

## 二、根因（已实测确认）

1. DVR 引擎（`AMDRSServ.exe`）每次点击录制时，需要找到 AMD 软件界面（CN，`RadeonSoftware.exe`）的 `CNEventWindowClass` 主窗口，发送一次「场景转换」消息后才开始录制。
2. 找窗口的方式是 `EnumWindows` 枚举全部窗口 + `GetClassNameW` 读取每个窗口的类名。
3. 该调用申请的类名缓冲区是 **520 字符（1040 字节）**，而事发线程栈上自缓冲区起只剩 **1024 字节**可用 → 请求越出线程栈顶 **16 字节** → user32 对整段目标范围的可写校验失败（`ERROR_NOACCESS` / 998）→ **所有窗口的类名都读不到** → 找不到目标窗口 → 静默放弃。
4. 余量只有 16 字节，且随线程调用链深度波动，所以成败是概率性的——重启有时能好一阵，有时不行。

## 三、修复原理

两处**等长改写**（文件大小不变、数字签名必然失效，因此两步必须配套）：

| 位置 | 原始 | 修复后 | 作用 |
| --- | --- | --- | --- |
| `AMDRSServ.exe` 文件偏移 `0x3686B` | `08 02`（0x208 = 520） | `00 01`（0x100 = 256） | 类名读取请求缩到安全长度（真实类名最长几十字符，256 足够） |
| exe 内嵌清单 | `uiAccess="true"` | `uiAccess="false"` | 补丁破坏签名后，声明 uiAccess=true 的程序会被 Windows 拒绝启动；改 false 后正常启动 |

修复后引擎以普通权限运行（它本来也不需要特殊权限）。

**支持的构建与 sha256 门禁**：

| 构建（驱动版本） | 原版 | 打补丁后 | 修复后 |
| --- | --- | --- | --- |
| 26.20.15.07（2026-10） | `ff26b09a…6fc3528` | `0dc22efa…30447e` | `ae4f3058…1aa66156e` |
| 26.20.15.02（2026-09） | `0f28b308…d5e450c9` | `1ae3fcc5…8194ba` | `72099cb6…7a5f840` |

两代文件等长（2628872 字节），补丁点、函数帧与清单位置完全一致，逐字节差异仅 0.05%（全部是版本串与签名哈希）——AMD 并未修复该处代码，只是把打过补丁的文件整体替换。脚本内置这张构建表（`patch_manifest.py` 的 `BUILDS`），会自动识别当前文件属于哪一代；适配其他版本时在表里新增一项即可。

所有脚本带 **sha256 门禁**：文件状态与目标构建不符（如 AMD 已更新程序）时明确拒绝动作，不会乱改。

## 四、环境与兼容性

- 实测环境：Windows 11 + AMD Software: Adrenalin Edition，驱动 **26.20.15.07**（2026-10）与 **26.20.15.02**（2026-09）两代均已实测；RX 7900 XT（RDNA3）。
- 依赖：PowerShell 5.1+（脚本自动请求 UAC 提权）；Python 3.8+（仅 `patch_manifest.py` 需要，`pefile` 为**可选**依赖——安装后多一层清单 XML 结构校验）。
- 脚本按 sha256 精确识别文件状态与构建代际（内置 26.20.15.02 / 26.20.15.07），**只对已验证的构建生效**；AMD 更新 `AMDRSServ.exe` 后补丁会失效，需重新适配（见第九节）。
- 其他 AMD 版本不一定适用；不适配时脚本会中止并说明，不会强行修改。

## 六、首次使用顺序（重要）

1. 先双击 **应用补丁.cmd**：在 `backup\` 生成官方原版备份（sha256 校验），并打上 2 字节补丁。
2. 再双击 **修复引擎启动.cmd**：补上清单修复（uiAccess true→false），经临时计划任务以普通权限重启引擎并校验存活；失败自动回滚。
3. 之后只需 **修复引擎启动.cmd** 一步（幂等：已修复则跳过）。
4. **重启电脑**，再点一次录制验收（见第十一节：不重启时引擎可能带管理员令牌，录制仍会失败）。

> 为什么需要两步：`修复引擎启动.cmd` 要求 `backup\` 里有一份 sha 吻合的原版备份才会动作，首次没有备份时它不会自动创建，需先用「应用补丁.cmd」生成。
> `backup\` 已在 `.gitignore` 中——AMD 官方原版二进制不随仓库分发（版权与体积原因），请在各机器上首次运行时自动生成，**不要删除**。

## 八、应急解卡（调试器法）原理

故障状态下：

1. 以管理员运行「启动解卡脚本.cmd」，cdb 附加到引擎进程。
2. 窗口出现 `TRACE_READY_CLICK_RECORD_ONCE` 后，**只点一次录制**。
3. 断点在 `GetClassNameW` 调用点命中后，把请求长度寄存器从 0x208 改成 0x100，强制完成一次窗口查找与场景转换；枚举结束自动分离。
4. 之后本会话的录制不再走枚举（转换状态被保持），直接可用。

该方法**不改磁盘文件**，适合在决定是否打补丁之前救急，或补丁暂不适用时使用。

调试器获取方式（脚本按顺序查找：`-CdbPath` 参数 > 环境变量 `DVR_CDB_PATH` > 同级的 `windbg-portable\amd64\cdb.exe`（本仓库不包含调试器，仅兼容既有部署）> PATH 中的 `cdb`）：

- Microsoft Store 安装「WinDbg」（内含 cdb）；
- 安装 Windows SDK 的 Debugging Tools；
- 已有便携版调试器：用 `-CdbPath` 指定，或设置环境变量 `DVR_CDB_PATH`（提权后环境变量仍然有效，推荐）。

## 九、AMD 更新之后

驱动/软件更新会替换 `AMDRSServ.exe`，补丁与清单修改一起失效：

- 重跑「修复引擎启动.cmd」重新打上，**然后重启电脑再测试**（脚本重启的引擎带管理员令牌，该形态下录制不会好）。
- 若提示「状态不符」，说明文件已换成新构建（sha 门禁过期）——**不要强行操作**。适配要做三件事：① 在 `backup\` 存一份新版原版；② 在 `patch_manifest.py` 的 `BUILDS` 表新增一项（orig / patched / fixed）；③ 在 `restore_original.ps1` 的 `$builds` 表新增同一项（`apply_manifest_fix.ps1` 自动从构建表读取，无需改）。偏移量通常不需要改（26.20.15.02 → 26.20.15.07 即如此，两代文件等长且补丁点一致）。

## 十、怎么判断「又坏了」

判据只有一个：**点一次录制，看有没有文件落盘**（你的录制输出目录）。

按顺序看，每一步都可能是终点：

1. 没反应 → 看最新 dvrlog 有没有 `Failed to send scene conversion to CN` → 有 = 老问题（补丁被覆盖或未生效，按第五节的表处置）。
2. 有没有 `SCENE_CONVERSION_DONE` → 有且仍不落盘，才需要怀疑别的原因（编码 / 磁盘 / 开关）。
3. `AMF_FILE_NOT_OPEN: Open() failed` **不是**故障标志——它在验收成功的会话里同样出现，位置固定在 `Instant replay has been started` 之前，属即时重放的常态噪声；成功与失败的分岔点是 scene conversion，不是它。

## 十一、已知现象（重要）

1. **修复后必须重启电脑再测试录制。** 修复脚本通过提权会话重启引擎时，引擎可能带上管理员令牌；实测该形态下录制**仍然失败**（2026-10-23：文件已确认修复、点击录制仍无反应、零落盘；重启电脑后引擎以普通权限拉起，一次成功、正常落盘）。重启后引擎会自动恢复普通权限形态。
   - 附带现象：管理员形态引擎写的 dvrlog 用普通权限读不到，此时无法取证。
2. 若脚本重启过 AMD 界面，**界面语言可能变成英文**——重开界面或重启电脑会自动恢复中文，所有设置不会丢。
3. 桌面录制开关由你在 AMD 软件里控制。关着时点录制，AMD 会弹窗提示开启，属正常流程。

## 十二、注意事项

1. 脚本会改写 `C:\Program Files\AMD\CNext\CNext\AMDRSServ.exe`，需要管理员权限；运行前确认 `backup\` 存在且未被删改。
2. 临时计划任务名 `DvrFixStartEngine` 由脚本自动注册与注销，无残留。
3. 本工具与 AMD 无任何关联；按「原样」提供，使用需自担风险。
